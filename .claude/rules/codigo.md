# Regras de código

- Funções pequenas, com um único propósito. Nomes descritivos > comentários.
- Comentários explicam o **porquê**, não o **o quê**.
- Trate erros explicitamente; nunca engula exceções em silêncio.
- Sem valores mágicos: use constantes nomeadas ou configuração.
- Não deixe código morto, `console.log`/`print` de debug ou TODO sem contexto.
- Siga o padrão que já existe no arquivo/pasta antes de inventar um novo.
- Validação de entrada sempre na borda (API, formulário, CLI).
